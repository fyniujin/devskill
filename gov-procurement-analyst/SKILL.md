## 多需求同时提出时的处理规则

> 评测反馈："如果一次说好几个需求，不知道系统会先处理哪个"。
> 本 Skill 明确以下优先级：

### 优先级从高到低

| 优先级 | 场景 | 判断条件 | 示例 |
|--------|------|----------|------|
| 1 | 投诉/质疑/时效敏感 | 涉及法定截止日 | "明天截止质疑，帮我写质疑函" |
| 2 | 背调已有目标 | 指定了企业名称 | "查一下XX公司的同时看他有没有买过同类型设备" |
| 3 | 已有具体项目 | 指定了项目链接/编号 | "分析这个项目 http://..." |
| 4 | 商机发现 | 想找项目 | "找北京的 IT 项目" |
| 5 | 知识查询 | 政策/流程 | "中小企业声明函怎么开" |

### 处理原则

1. **安全相关永远优先**：质疑投诉 > 常规分析
2. **具体 > 笼统**：指定了项目链接 > 只说"找项目"
3. **连锁任务合并处理**：先说"查 A 公司"，紧接着问"他有没有做过 XX"，会合并成一次查询
4. **并行采集**：多个数据源同时采集时，进度条会实时汇报，不阻塞对话

```

例如：CMMI3/ISO27001/系统集成壹级/信息安全等级保护三级

错误格式：
✗ CMMI3，ISO27001，系统集成壹级（用中文逗号）
✗ 1.CMI3 2.ISO27001（加了编号）
✗ 我们有证书（太模糊）
```

## 详细功能说明（完整版）

> 以下为 19 个模块的完整工作流、输入输出模板和边界条件。

### 1. 商机发现与智能监控

**输入**：行业/地区/金额/采购方式（可选，不填用默认）
**输出**：匹配度排序的商机日报

**工作流**：
```
1. 读取用户订阅配置（如未配置 → 默认全行业/全国/不限金额）
2. 采集策略判断：
   - 已安装 requests+bs4 → 生产级爬虫模式：
     a. psutil 检测 CPU/内存 → 动态分配并发线程数
     b. 多源并发采集：ccgp.gov.cn + 31省分网（按用户地区优先级排序）
     c. 增量采集：仅抓取上次采集后新增的公告（记录最后采集时间戳）
     d. 错误重试：失败域名进入冷却队列，30分钟后重试
     e. **双选择器自愈**：
        - 每个采集源配主选择器+备选择器（两套CSS/XPath）
        - 主选择器失效（返回空/解析失败）→ 自动切换备选择器
        - 双选择器均失效 → 记录待修清单 → 降低该源调度权重（权重 = 成功率 × 0.8）
        - 页面结构哈希监测：每次采集后存储页面结构 hash → hash 变化预警（可能改版）
   - 未安装 requests+bs4 → 降级模式：
     a. 使用 WebFetch 内置工具采集 ccgp.gov.cn 国家级平台
     b. 功能可用但采集源减少（仅国家级，无省级）
3. 解析 HTML 提取关键字段（bs4 解析 → 结构化数据）
4. 计算匹配分数（行业30%+资质25%+业绩20%+地区15%+金额10%）
5. 按匹配度降序输出
6. 更新采集配额计数器（gov_quota.db）
```

**多源并发控制**（psutil 硬件感知）：

| 硬件配置 | 并发线程数 | 请求间隔 | 每小时配额 |
|---------|-----------|---------|-----------|
| 4核/8GB | 2 | ≥3秒 | ≤120次 |
| 8核/16GB | 4 | ≥3秒 | ≤240次 |
| 16核/32GB+ | 8 | ≥3秒 | ≤480次 |

**定时采集任务**（WorkBuddy automation）：
```
- 频率：每日 08:00 / 12:00 / 18:00
- 范围：用户订阅地区 + 行业
- 输出：增量商机日报（仅展示新公告）
- 推送：可选推送到企业微信/钉钉（需配置连接器）
```

**匹配度评分**：

| 维度 | 权重 | 高匹配(≥80) | 中匹配(60-79) | 低匹配(<60) |
|------|------|-------------|---------------|-------------|
| 行业匹配 | 30% | 完全一致 | 相关/同类 | 跨行业 |
| 资质匹配 | 25% | 100%覆盖 | 覆盖≥60% | 覆盖<60% |
| 业绩匹配 | 20% | ≥3个同类 | 1-2个同类 | 无同类 |
| 地区便利 | 15% | 本地 | 同省 | 跨省 |
| 金额匹配 | 10% | ±50%范围内 | ±100%范围内 | 超范围 |

### 16. AI 投标书撰写引擎

**定位**：本模块 v4.7 深度升级，将标书生成从「模板填空」升级为「智能生成 + 人工审核」。目标是把技术方案章节等耗时最长的环节自动化，用户只需审核修改而非从零编写——标书撰写时间从 3-5 天缩短到 2-4 小时。

**全流程闭环**：资质自动填充 → 技术方案智能生成 → 项目案例引用 → 内容对齐检查 → 格式合规检查 → 导出 Word/PDF → 存档复用。

#### 16.1 技术方案智能生成（v4.7 优化扩展）

**输入**：招标文件全文/链接 + 评分标准 + 企业画像
**输出**：各章节初稿 + 6 大技术方案子块 + 评分项对齐提示

**工作流**：
```
1. 接收招标文件 → 提取技术要求与评分标准
2. 按招标技术要求生成技术方案初稿，拆分为 6 个独立子块：
   - ① 技术路线选择（对比候选方案+选型理由，对齐技术评分项）
   - ② 实施方案（分阶段实施步骤+技术细节+关键难点应对）
   - ③ 人员配置（项目组织架构+岗位职责+人员数量测算）
   - ④ 设备清单（软硬件配置表+品牌型号+数量+技术参数）
   - ⑤ 质量保证措施（质量管理体系+过程管控+验收标准）
   - ⑥ 进度计划（甘特图式里程碑+关键路径+交付节点）
3. 生成配套章节：项目理解与分析 / 售后服务方案 / 项目团队简历
4. 每个子块附【评分项对齐提示】→ "对应评分标准第 X 项，占 Y 分"
5. 标注【待审核】占位符 → 用户只需审核修改，不从零编写
```

**生成方式**：jinja2 模板（素材库 16.10）+ LLM 按评分项/技术要求分段生成
**降级方案**：无 jinja2 → 使用内置基础模板；无 LLM → 输出结构化章节骨架供手动填写
**输出模板**：见"输出模板"章节·标书生成模板

#### 16.2 评分项自动对齐检查

**输入**：生成的标书 + 招标文件评分标准
**输出**：覆盖矩阵 + 0-100 自评分 + 缺失清单 + 补遗建议

**工作流**：
```
1. 解析评分标准逐条
2. 每条评分项 → grep/语义匹配标书章节
3. 输出三状态：已覆盖 / 部分覆盖 / 未覆盖
4. 自评分数 = Σ(已覆盖项权重) + Σ(部分覆盖项权重 × 0.5)
5. 缺失清单 → 每条给出补遗建议
```

**边界条件**：
- 评分项超出标书主题范围 → 标记为"不可得分"并说明
- 模糊评分项 → 提示"建议与采购方核实评分细则"

#### 16.3 历史标书复用库

**输入**：当前项目描述 + 品类标签
**输出**：相似标书推荐 + 一键复用

**存储**：加密 SQLite，存于 `~/.workbuddy/output/gov_archive.db`（符合死规则 #12 运行时例外）

**工作流**：
```
1. 标书生成完成后自动存档（品类标签+评分结构+企业名占位）
2. 下次类似项目 → 自动检索品类相似度（关键词+品类编码匹配）
3. 匹配到历史标书 → 推荐复用章节列表
4. 一键替换：企业名/人员/业绩 → 自动更新时效内容
```

**相似度匹配**：
| 相似度 | 处理方式 |
|--------|----------|
| ≥80% | 推荐完整复用，提示"无需重写，一键替换即可" |
| 60-79% | 推荐章节复用（技术方案/售后可复用，业绩需更新） |
| <60% | 不推荐复用 |

#### 16.4 标书导出为 Word/PDF

- 无 python-docx → 输出 Markdown，可复制到 Word
- 无 reportlab → 仅输出 .docx

#### 16.5 投标报价测算辅助

**输入**：成本分解项
**输出**：总成本 + 毛利 + 建议报价区间

**工作流**：
```
1. 引导输入：硬件成本 / 软件成本 / 人天（人×天×单价）/ 服务成本
2. 自动计算：总成本 = 硬件 + 软件 + 人力 + 服务 + 5% 管理费
3. 毛利率推算：基于历史数据和 BidDecisionEngine 报价策略模型
4. 最优报价 = 总成本 × (1 + 目标毛利率) ∩ [预算 × 0.7, 预算 × 0.98]
5. 输出：成本分解表 + 建议报价区间 + 竞对对比（如有数据）
```

#### 16.6 资质缺漏预警

**输入**：招标公告资质要求 + 企业画像库
**输出**：三色清单 + 最快获取路径

**工作流**：
```
1. 交叉比对资质要求 vs 企业画像
2. 输出三色清单：
   🟢 已具备资质 → 标注有效期
   🟡 即将过期资质（<30天）→ 提醒续期
   🔴 缺失资质 → 标注"一票否决项"或"加分项"
3. 缺失资质 → 给出最快获取路径：
   - 例："ISO27001 认证周期约 8-12 周，建议立即启动"
   - 例："涉密资质需向国家保密局申请，周期 3-6 个月"
4. 一票否决项缺失 → "⚠️ 强烈建议放弃投标或联合具备资质的合作伙伴"
```

**输出模板**：

```
🔴 缺失：信息系统运维三级(一票否决项) → 建议：① 联合具备运维资质的合作伙伴投标 ② 最快获取路径：向当地工信部门申请，周期约4-6周

⚠️ 存在一票否决项缺失，综合建议：谨慎参与投标
```

#### 16.7 企业资质自动匹配填充（v5.2 升级OCR离线化）

**输入**：企业资质文件（营业执照/资质证书/ISO 认证等）+ 标书章节结构
**输出**：结构化资质数据 + 自动填充到标书对应章节（资质符合性/企业简介/证明材料清单）

**定位**：v5.2 将在线OCR替换为本地PaddleOCR，解决外勤场景网络不稳定时的资质识别问题。新增证书版式库（3大类证书字段定位规则），识别结果直接填充到标书资质章节（对接模块25.4）。

**工作流（A+B+C 三级混合，本地优先）**：
```
1. 接收资质文件（PDF/图片/用户描述）
2. 分类型解析：
   - 文本型 PDF → pdfplumber 直接提取文字（纯本地，方案A）
   - 图片型证书 → 优先PaddleOCR本地离线识别（方案B，推荐安装）
   - PaddleOCR不可用 → 降级为多模态识别（方案C，环境具备时）
   - OCR均不可用 → 降级引导手动录入关键字段（方案A兜底）
3. 证书分类（按标题关键词匹配版式库：营业执照/行业资质/ISO认证）
4. 字段定位（按版式库规则提取关键字段：名称/编号/等级/发证机关/有效期）
5. 结构化抽取字段：证书名称 / 编号 / 等级 / 发证机关 / 有效期 / 经营范围 / 统一社会信用代码
6. 关键字段校验（统一社会信用代码18位格式/资质等级匹配招标要求/有效期覆盖/经营范围包含招标标的）
7. 交叉比对招标资质要求（对接 16.6 资质预警）
8. 自动填充到标书章节：
   - 「资质符合性说明」→ 逐项对应招标要求列出已具备资质
   - 「企业基本情况」→ 注册资本/成立时间/经营范围
   - 「证明材料清单」→ 需随标附上的资质复印件清单
9. 填充内容标注【自动填充·待核对】→ 用户确认原件一致后定稿
```

**证书版式库**（3大类证书的字段定位规则）：

| 证书类型 | 定位字段 | 定位规则 |
|---------|---------|---------|
| 营业执照 | 名称/统一社会信用代码/法定代表人/成立日期/经营范围 | 标题下方第1-5行，关键词触发 |
| 行业资质证书 | 证书名称/编号/等级/发证机关/有效期 | "证书"关键词区域，编号格式匹配 |
| ISO认证证书 | 证书编号/认证范围/发证日期/有效期至/认证机构 | "认证"关键词区域，编号格式匹配 |

**边界条件**：
- 证书为扫描件且无OCR → 提示"请手动录入证书名称/编号/有效期，我来填充"
- 识别置信度低 → 标注"⚠️ 识别可能有误，请核对原件"
- 涉密/敏感证件 → 仅本地处理，不上传，不外发

**降级方案**：
- 无PaddleOCR → 降级为多模态识别（方案C，需环境支持）
- 无多模态 → 图片型证书走手动录入
- 无 pdfplumber → 引导手动录入
- **全程可用最低限度**：纯手动录入 + 模板填充，功能不中断

#### 16.8 同类项目经验自动引用（v4.7 新增）

**输入**：企业历史项目清单 + 招标文件业绩要求
**输出**：最相关项目案例 + 自动填入业绩章节

> 与 16.3 区别：16.3 是「整份历史标书」级复用；16.8 是「单个项目案例」级智能匹配引用到业绩章节，粒度更细。

**工作流**：
```
1. 读取用户历史项目清单（项目名/客户/金额/时间/技术栈/成果）

3. 相关性打分（每个历史项目 vs 招标要求）：
   - 行业匹配 35% + 技术栈匹配 25% + 金额匹配 20% + 时效 15% + 客户级别 5%
4. 按分数降序，选取满足业绩要求数量的最相关案例
5. 自动填入「类似项目经验」章节：

```

|--------|----------|
| ≥80% | 首选引用，标注"高度相关，重点展示" |
| 60-79% | 备选引用，补充说明相关性 |
| <60% | 不推荐，仅在业绩数量不足时补位 |

**边界条件**：
- 历史项目为空 → 提示"暂无历史项目，请先录入或考虑联合体投标"
- 业绩数量不足招标要求 → 明确预警并给出应对建议

**输入**：生成的标书 + 招标文件格式要求
**输出**：格式合规检查报告（逐项通过/警告/不通过 + 修正建议）

```
   - 页码 / 页眉页脚 / 目录
   - 密封要求（正副本数量/密封方式/骑缝章）
   - 签字盖章位置（法定代表人签字/公章/骑缝章/授权委托书）
   - 投标函格式 / 报价表格式
3. 输出三态清单：✅ 通过 / ⚠️ 警告 / ❌ 不通过
4. 每个不通过项 → 给出具体修正建议
5. 生成「投标前格式自检清单」供打印核对
```

**核对项对照表**：

**边界条件**：

### 17. 竞争对手深度画像

**定位**：本模块是 v4.8 核心升级，将模块 4「供应商背调」从基础信息采集升级为深度战略分析，让投标人从"知道对手是谁"升级到"知道对手会怎么出牌"。

**数据源扩展**（从单一中标公告扩展到多源）：
```
历史中标数据 → 报价/中标方/中标金额/下浮比例
企业工商信息 → 法人变更/注册资本/经营范围/股东变更
资质变更数据 → 资质升级/增项/被降级/吊销
司法诉讼 → 合同纠纷/劳动争议/知识产权诉讼
招聘信息 → 关键岗位（项目经理/技术负责人）变动
联合体/分包 → 合作关系网络（同一项目中出现过的组合）
```

> **存储**：`~/.workbuddy/output/gov_competitor.db`（运行时生成，符合死规则运行时例外）

#### 17.1 报价策略分析

**输入**：竞争对手名称 + 历史中标数据
**输出**：报价规律报告（下浮比例/价格分策略/低价冲标倾向）

**工作流**：
```
1. 采集竞对近 2-3 年历史中标公告
2. 提取关键指标：中标金额/预算金额/下浮比例/评分方法
3. 统计规律：
   - 平均下浮比例 = Σ(中标金额/预算)/n
   - 低价冲标倾向 = 中标价格 < 预算×70% 的频次占比
   - 价格分策略 = 最低评标价法 vs 综合评分法下的报价分布
4. 对比本次项目预算 → 预测竞对报价区间
5. 输出报价策略分析报告
```

**输出模板**：见"输出模板"章节·报价策略分析模板

#### 17.2 优势领域图谱

**输入**：竞争对手名称 + 历史中标数据
**输出**：优势领域分布图（中标频次最高品类/地区/金额区间）

**工作流**：
```
1. 统计竞对历史中标品类分布（按政府采购品目分类）
2. 统计地区分布（哪个省市中标最多）
3. 统计金额区间分布
4. 统计评分方法偏好（竞对在哪种评分法下中标率高）
5. 输出可视化雷达图（品类+地区+金额+评分法四维度）
```

#### 17.3 弱势领域识别

**输入**：竞争对手名称 + 投标历史数据
**输出**：弱势领域报告（屡投不中品类 → 市场缝隙机会）

**工作流**：
```
1. 识别竞对"屡投不中"品类（投标次数≥2但中标率=0）
2. 识别"高频投标低中标率"品类（投标≥3次且中标率<20%）
3. 输出市场缝隙建议 → "竞对在XX品类屡投不中，建议差异化突进"
```

#### 17.4 关联关系网络

**输入**：竞争对手名称 + 联合体/分包数据

```
3. 构建关联网络图：节点=企业，边=联合/分包关系

```

**输出模板**：见"输出模板"章节·关联网络图模板

#### 17.5 人员流动追踪

**输入**：竞争对手名称 + 招聘信息/项目经理变更记录

### 18. 评分预测模型

**定位**：本模块是 v4.8 核心升级，基于历史评标数据对当前项目进行打分预测，帮助用户判断中标概率。

**双轨迭代机制**：
```
规则引擎（冷启动）：评分标准明确→基于规则计算→初期可用，准确度随数据积累提升
数据积累（精度提升）：历史数据越多→统计权重越高→预测准确度逐步提升
```

**数据源**：
```
历史评标数据 → 得分/排名/基准价/报价分布
招标文件 → 评分标准/权重/评标办法
企业画像 → 资质/业绩/人员
竞对画像 → 模块17输出的竞对报价预测
```

> **存储**：`~/.workbuddy/output/gov_scoring.db`（运行时生成，符合死规则运行时例外）

#### 18.1 技术分预测

**输入**：招标文件评分标准 + 用户资质匹配度 + 历史同类项目得分
**输出**：技术分区间预测 + 失分点分析

**工作流**：
```
1. 解析招标文件评分标准（技术分各评分项+权重）
2. 基于用户企业画像逐项评估：
   - 资质匹配 → 是否有该项要求的资质
   - 业绩匹配 → 是否有同类项目业绩
   - 技术方案 → 方案覆盖度评分（LLM辅助评估，失败降级为规则打分）
   - 人员配置 → 人员资质/数量是否满足
3. 加权计算：技术分 = Σ(各评分项权重×预估得分率)
4. 输出技术分区间（乐观/基准/悲观）+ 失分点清单 + 改进建议
```

**降级方案**：
- 无历史同类项目得分 → 纯规则引擎评估，标注置信度"低"
- LLM不可用 → 仅使用规则打分，跳过LLM辅助评估

#### 18.2 商务分预测

**输入**：用户历史报价策略 + 竞争对手报价预测（17.1）
**输出**：商务分排名预测

**工作流**：
```
1. 分析用户历史报价策略（下浮比例/报价区间）
2. 预测本次竞对报价区间（基于17.1报价策略分析）
3. 模拟评标基准价计算（基于不同报价组合）
4. 预测商务分排名（用户报价 vs 竞对报价 → 得分排序）
5. 输出商务分排名区间（乐观/基准/悲观）
```

#### 18.3 价格分预测

**输入**：预算金额 + 有效报价区间 + 基准价算法
**输出**：最优报价 + 价格分测算

**工作流**：
```
1. 解析招标文件价格分计算公式：
   - 最低评标价法：价格分 = (评标基准价/报价) × 价格权值
   - 综合评分法：按招标文件公式计算
2. 确定评标基准价算法（如：去掉最高最低后平均/平均下浮等）
3. 模拟不同报价下的价格分：
   - 报价 = 预算 × 0.95 → 价格分 = X
   - 报价 = 预算 × 0.90 → 价格分 = Y
   - 报价 = 预算 × 0.85 → 价格分 = Z
4. 输出最优报价建议（价格分与利润率的平衡点）
```

#### 18.4 综合中标概率

**输入**：技术分预测 + 商务分预测 + 价格分预测
**输出**：中标概率区间 + 信心指数 + 敏感性分析表

**工作流**：
```
1. 综合三维度得分：总分 = 技术分 + 商务分 + 价格分
2. 模拟排名：用户总分 vs 预测竞对总分分布
3. 计算中标概率 = 用户排名第1的次数 / 总模拟次数
4. 输出：
   - 中标概率区间（乐观/基准/悲观）
   - 信心指数（高/中/低，取决于数据完整度）
   - 敏感性分析表："如果报价为X，则中标概率Y%"
```

**敏感性分析表**：
| 报价（万元） | 价格分 | 总分 | 预测排名 | 中标概率 |
|-------------|--------|------|----------|----------|
| 预算×0.95 | X1 | Y1 | 1-2 | 85% |
| 预算×0.90 | X2 | Y2 | 1 | 92% |
| 预算×0.85 | X3 | Y3 | 1 | 95% |
| 预算×0.80 | X4 | Y4 | 1 | 97% |

**输出模板**：见"输出模板"章节·评分预测模板

**边界条件**：
- 无历史数据 → 纯规则引擎输出，标注置信度"低"，建议"需积累数据"
- 数据不足 → 提示"当前数据量有限，预测仅供参考"
- LLM不可用 → 跳过LLM辅助评估，纯规则打分

## 运行稳定性保障

> 评测反馈："复杂场景下偶有卡顿或提示不够明确"。以下是稳定性保障机制。

### 网络采集稳定性

| 场景 | 处理方式 | 用户提示 | 预计恢复时间 |
|------|----------|----------|-------------|
| 单个网站超时 | 自动切换下一个网站，后台重试失败网站 | "⚠️ {网站} 采集较慢，已优先使用其他网站数据，后台继续尝试..." | 无需等待，立即可用 |
| 网络断开 | 自动重试3次，每次间隔5秒 | "🔄 网络连接不稳定，正在重试... (第{attempt}次)" | 5-15秒 |
| AI 回答不稳定（卡顿） | 自动检测并重新生成 | "⏳ 正在优化回答，请稍候..." | 3-10秒 |
| 所有网站均不可访问 | 切换到 demo 模式，使用缓存/示例数据 | "⚠️ 当前无法连接政府采购网站，已切换到演示模式。您可以：① 检查网络稍后重试 ② 直接提供项目链接分析" | 用户自定 |
| 响应超时（>30秒） | 中止当前任务，提示用户简化需求或重试 | "⏱️ 任务处理超时，建议：① 缩小搜索范围（如指定具体地区）② 直接提供项目链接 ③ 稍后重试" | 立即释放 |

### 数据缓存机制

```
采集结果自动缓存：
- 公告列表：24 小时内有效
- 公告详情：72 小时内有效
- robots.txt：24 小时内有效
- 企业信息：7 天内有效

重复请求处理：
- 相同页面 24 小时内不重复请求
- 优先使用缓存数据
- 缓存标注："📦 缓存数据，更新时间：{time}"
```

### AI 回答质量保障

```
置信度分级：
- 🟢 高置信度：数据完整，建议可靠
- 🟡 中置信度：部分数据缺失，建议供参考
- 🔴 低置信度：数据严重不足，仅供参考，请人工核实

自动触发重新生成的条件：
- 用户反馈"不对"/"重来"/"重新"
- 检测到回答中关键数据缺失
- 回答长度 < 50 字且包含"可能"
```

### 异常处理原则

```
所有异常都遵循：
1. 不崩溃：即使出错也返回友好提示
2. 有备选：主方案失效时自动切换备选方案
3. 说明白：用大白话告诉用户出了什么问题、该怎么做
4. 给方案：不只告诉"失败了"，告诉"现在可以做什么"

示例：

❌ "HTTP 403 Forbidden"（技术化）
✅ "⚠️ 该网站拒绝了自动访问请求，可能是因为反爬限制。没关系，我已经跳过了它，继续用其他网站的数据给您出报告。"

❌ "请求超时"（太简单）
✅ "⏱️ 采集超时了，可能是网站太慢。已自动重试，如果还不行建议您：① 换个时间段再试 ② 直接给我项目链接，跳过采集直接分析"
```

### 性能优化建议

```
让 Skill 跑更快的 3 个技巧：

1. 指定具体范围
   ❌ "找全国项目"（慢，需要查 31 个省）
   ✅ "找北京市 IT 项目"（快，只查 1-2 个网站）

2. 直接给链接
   ❌ "帮我看看有没有这个项目..."（需要先搜索）
   ✅ "分析这个项目 http://www.ccgp.gov.cn/..."（直接分析，跳过采集）

3. 配置企业信息后再搜索
   ❌ 不配置就搜索（需要全量匹配，慢）
   ✅ 先配置企业信息（匹配算法更精准，越快越准）
```

### 🔄 投标实操（新增高频问题）

**Q13：投标保证金怎么交？交到哪里？**
**A**：缴纳方式通常有三种：①银行转账（最常用）②银行保函③保证保险。缴纳账户必须是**采购人指定账户**（在招标文件"投标人须知"部分）。**关键提醒**：必须从**公司基本户**转出（不能从个人账户转），汇款备注写"XX项目投标保证金"。Skill 可分析具体项目的缴纳截止时间和退还规则。

**Q14：投标被废标了怎么申诉？**
**A**：废标后可采取四步：①**核实废标原因**：仔细阅读废标通知，确认是"无效投标"还是"废标"（区别很大）→ ②**判断是否合规**：废标条件必须在招标文件中明示，不能临时创设 → ③**质疑**：在知道或应知其权益损害之日起7个工作日内向采购人提出书面质疑 → ④**投诉**：质疑答复不满意可在答复期满后15个工作日内向同级财政部门投诉。Skill 帮你生成质疑函和投诉书模板。

**Q15：中标后放弃有什么后果？**
**A**：后果较严重：①投标保证金不予退还 ②由财政部门责令改正，给予警告 ③情节严重者，列入不良行为记录名单，1-3年内禁止参加政府采购 ④给采购人造成损失的，需承担民事责任。**建议**：除非有重大项目冲突，不建议轻易放弃。

**Q16：联合体投标怎么操作？**
**A**：关键点：①签订《联合体协议书》，明确牵头方和各方分工 ②联合体各方均满足招标文件规定的资格条件 ③资质就低认定（联合体中有同类资质的，按等级较低的单位确定资质等级）④联合体各方应当共同签订合同，承担连带责任。Skill 提供联合体协议模板。

**Q17：政府采购合同可以分包吗？**
**A**：有条件允许：①中标供应商需经**采购人同意** ②只能分包**非主体、非关键性工作** ③接受分包的人必须具备相应条件 ④中标供应商就分包项目向采购人负责，接受分包的人承担连带责任。**禁止**：转包（把全部工程转给别人）是违法的。

### ⚖️ 合规与法律

**Q18：质疑函/投诉书应该什么时候递交？**
**A**：时间节点把握如下：

| 程序 | 时限 | 起算日 |
|------|------|--------|
| 质疑 | 知道权益受损后**7个工作日** | 知道或应当知道之日 |
| 投诉 | 质疑答复期满后**15个工作日** | 采购人答复期满之日 |
| 行政复议 | 知道行政行为之日起**60日** | 收到投诉处理决定之日 |
| 行政诉讼 | 知道行政行为之日起**6个月** | 收到投诉处理决定之日 |

**Q19：投标保证金可以用什么形式缴纳？**
**A**：根据《政府采购法实施条例》第33条，投标保证金可以是：①**银行转账**（最常见）②**银行保函**（推荐，资金占用少）③**保证保险**（部分省市已推行）④**支票/本票**。**禁止使用**：现金。金额不得超过项目预算的2%，有效期应当超出投标有效期30天。

**Q20：中小企业声明函需要什么附件？**
**A**：声明函是自我声明（自己写自己承诺），不需要外部审批。但税务机关和财政部门**事后抽查**时，需能证明你确实属于中小企业。建议留存：①《中小企业声明函》（按采购人提供格式）②企业从业人员/营业收入/资产总额等证明材料（可能需要近3年审计报告或纳税申报表）③如联合体投标，需额外提供联合体协议和各方声明函。

**Q21：v5.0.0 的「真实数据接入」是什么？和以前有什么区别？**
**A**：v5.0.0 之前模块1「商机发现」使用 WebFetch 内置工具做 demo 演示。v5.0.0 起升级为生产级爬虫，直接请求 ccgp.gov.cn + 31省分网真实页面，数据完整度和时效性大幅提升。需要安装 `requests` + `beautifulsoup4`（发送 `"安装依赖"` 即可）。未安装时自动降级为 WebFetch，功能可用但采集源减少。

**Q22：采集配额仪表盘显示「配额告警」怎么办？**
**A**：告警表示当前采集频率接近平台限制（如单域名 >40次/小时）。处理方式：①暂停当前采集，等待下一个小时窗口 ②切换到其他省份平台采集 ③降低定时任务的采集频率（发送 `"调整采集频率"`）。24小时窗口重置后自动恢复。

**Q23：意图路由器如何减少误触发？提问有什么技巧？**
**A**：意图路由器采用三级消歧：①核心词精确匹配（如"写标书"→模块16）②同义词扩展匹配（如"帮我写投标文件"→模块16）③上下文感知（如对话历史在谈"竞争对手"时，"分析"优先匹配模块17而非模块2）。**最佳提问技巧**：一句话一个任务 > 一句话多个任务；用具体名词（"XX公司"、"http://..."）> 笼统代词（"这个"、"那个"）。

**Q24：v5.1.0 的「数据飞轮」是什么？**
**A**：数据飞轮是 v5.1.0 的核心升级理念——把每次中标结果、投标经验、竞对动态都沉淀为本地数据资产，数据越多分析越准，越准中标越多，越多数据又进一步反哺分析。飞轮包含5个引擎：中标结果回流（采集中标公告入库）、行业价格指数（聚合均价与分位数）、复盘链自动串联（中标→复盘→入库一条链）、竞对实时监控（关注清单+变更检测+推送）、爬虫失效自愈（双选择器+降权重调度）。首次使用数据量较少，随着使用积累，分析准确度会持续提升。

**Q25：行业价格指数怎么用？**
**A**：价格指数是衡量某行业某区域某时期中标价格相对水平的指标（基准期=100）。**用途①**：投标报价参考——查看目标品类在目标区域的P25/P50/P75分位数，结合评分方法计算最优下浮比例。**用途②**：异常报价识别——报价超出P75或低于P25时触发预警（模块19增强）。**查看方式**：发送"价格指数"或"XX行业价格指数"，输出指数表+趋势曲线+分位数价格。

**Q26：复盘链自动触发需要什么条件？**
**A**：需要同时满足：①模块6「中标结果跟踪」执行后 ②gov_knowledge.db 中有用户参与该项目的投标记录（通过项目编号或名称相似度>0.7匹配）。满足后自动弹出复盘模板，用户确认即可生成完整复盘报告并归档。**注意**：首次使用知识库为空，需先积累投标复盘记录后复盘链才能自动串联。

**Q27：竞对监控怎么配置？推送频率是多少？**
**A**：发送"配置关注竞对" → 输入竞对名称清单（每行一家）→ 选择关注维度（中标/工商/资质/司法/招聘）。**推送频率**：定时任务每日 08:00/12:00/18:00 采集，检测到变更立即推送（企微/钉钉卡片，需配置 webhook）。**存储**：竞对动态时间线永久保存，可按竞对名称检索历史动态。

**Q28：爬虫自愈机制是什么？双选择器都失效怎么办？**
**A**：每个采集源配主选择器+备选择器两套CSS/XPath路径。主选择器失效时自动切换备选择器；双选择器均失效时记录待修清单，降低该源调度权重（暂停采集），每日重试待修清单。**用户操作**：发送"爬虫健康"查看自愈状态报告；发送"修复采集源"手动更新CSS路径。**影响**：双失效期间该源数据暂停采集，其他源不受影响。

**Q29：v5.2 的「标书协作引擎」怎么用？**
**A**：发送"创建标书任务" → 输入项目名和投标截止时间 → 自动拆解章节任务表（章节/负责人/状态/截止）。团队成员编辑章节时自动锁定防并发覆盖，全部完成后触发合并审校（全文一致性检查）。**存储**：章节锁表和版本历史存于 `~/.workbuddy/output/gov_collab.db`（运行时生成）。**注意**：仅支持本 Skill 管理的章节文件，外部文件需导入后协作。

**Q30：移动盯标推送怎么配置？推送频率是多少？**
**A**：发送"配置关注词" → 3步完成配置：①输入关注关键词（如"IT运维,系统集成"）②选择关注区域（如"北京,广东"）③设定金额范围（如50-500万）。**推送频率**：定时任务每小时扫描一次，命中即推送。**去抖规则**：同一采购人+同品类24小时内只推送1条；标题相似度>0.85视为同类公告合并推送。**每日上限**：20条，超出合并为摘要推送。需先配置企微/钉钉webhook地址。

**Q31：语音输入指令支持哪些场景？识别不准怎么办？**
**A**：v5.2 支持口语化指令识别，覆盖：商机发现（"查一下苏州的医疗设备标"）、盯标推送（"把这个标加关注"）、企业背调（"看看XX公司有没有问题"）、投标分析（"这个标能不能投"）、资质预警（"资质快到期了帮我看看"）、复盘查询（"我们上次投的怎么样"）。**识别不准时**：①补充关键信息（区域/品类/操作对象）②切换精确触发词 ③发送"精确模式"关闭消歧，直接使用L1核心词。

**Q32：资质OCR离线化需要安装什么？识别不准怎么办？**
**A**：推荐安装 `paddleocr` + `paddlepaddle`（发送"安装PaddleOCR"引导）。**识别不准时**：①确保证书图片清晰、光线充足、无遮挡 ②检查证书类型是否在版式库中（营业执照/行业资质/ISO认证）③置信度<85%时标注"⚠️ 待核对"，需人工确认。**降级方案**：无PaddleOCR时自动降级为多模态识别或手动录入，功能不中断。

**Q33：合规审计双档合并是什么？NetworkX必须安装吗？**
**A**：v5.2 将模块5（基础9项规则检测）与模块19（围标增强4项图分析）合并为一次触发、两档输出。**基础档**：纯规则检测（发售期/截止时限/澄清时限等9项），无需额外依赖，**始终可用**。**图分析档**：NetworkX图分析（多跳关联路径+异常报价模式+历史行为分析+人工复核预警），**推荐安装**（发送"安装NetworkX"引导）。未安装时输出"图分析未运行"标注，不影响基础档结果。

## 智能洞察引擎（超越执行层的战略增值）

> 评测反馈："缺少让人眼前一亮的洞察或建议"。本 Skill 不只是**帮你做事**，更**帮你想清楚**。

### 6 类增值洞察

每次分析（商机发现、投标决策、企业背调）时，Skill 会自动附加以下至少 2 类洞察：

| 洞察类型 | 触发时机 | 一句话价值 | 示例 |
|----------|----------|-----------|------|
| 🎯 **战略判断** | 市场分析/投标决策 | 告诉你"该不该打这个市场" | "你在该品类的中标率仅12%，建议先在周边城市积累3个同类业绩后再进省会" |
| 💸 **利润预警** | 报价分析/成本估算 | 告诉你"这个标值不值得投" | "该项目预算仅¥80万，但技术要求需5人团队8周交付，人天成本预计¥65万，利润率仅19%，低于行业平均22%" |
| 🔮 **趋势预判** | 商机发现/政策分析 | 告诉你"下一步棋怎么走" | "XX市近3月办公软件采购频次增长35%，预计Q3有大规模更新潮，建议提前储备方案和报价" |
| ⚠️ **雷区扫描** | 合同分析/背调/合规 | 告诉你"钱在哪但别踩线" | "该项目评分方法中'本地服务'占15分且要求'本地注册满3年'，你注册仅1年，此项基本不得分" |
| 🤝 **竞对分析** | 投标决策 | 告诉你"你的真正对手是谁" | "近2年同品类中标记录中，A公司出现4次、均价下浮8%，B公司出现2次、均价下浮15%，推测A是你的主要对手" |
| 🧩 **关联推荐** | 所有场景 | 告诉你"你可能忽略的机会" | "你查的这个采购人是XX局，他们近6个月有3个IT运维项目，总预算¥380万，建议纳入长期跟踪" |

### 智能洞察的生成逻辑

```
数据分析 + 模式识别 + 行业知识 → 洞察
    │
    ├─ 定量洞察：基于历史数据的统计发现
    │   例："你投了8个标只中了2个（25%），低于行业平均35%"
    │
    ├─ 定性洞察：基于法规/政策/经验的推理
    │   例："这个项目要求'本地售后团队'但你注册在外省，建议考虑与当地服务商合作"
    │
    └─ 前瞻洞察：基于趋势的前瞻性判断
        例："该品类采购周期通常Q4放量，现在提前接触采购人可以摸清需求"
```

### 如何在报告中获取洞察？

Skill 在以下模块的输出中会自动附加「💡 Insight」板块：

1. **商机日报** → 每个匹配项目附加 1 条匹配洞察 + 日报末尾附加 1 条综合趋势洞察
2. **投标决策报告** → SWOT 之后附加 1 条关键风险洞察 + 1 条竞对策略洞察
3. **企业背调报告** → 综合评级之前附加 1 条关联关系洞察
4. **合同分析** → 每个风险条款附加 1 条修改后的法律后果预判
5. **政策咨询** → 建议行动之前附加 1 条影响规模估算
6. **【v5.2 新增】盯标推送** → 推送卡片附加 1 条匹配洞察（为何命中+品类趋势）
7. **【v5.2 新增】合并审校报告** → 审校总结附加 1 条质量洞察（全文一致性评分+改进建议）
8. **【v5.2 新增】合规合并报告** → 综合评级附加 1 条风险洞察（围标特征模式识别+历史行为关联）

## 数据采集策略（重点合规要求）

### 数据采集原则

1. **仅采公开信息**：法律规定必须公开的采购公告/中标结果
2. **遵守 robots.txt**：每次请求前检查，拒绝爬取 Disallow 路径
3. **频率控制**：同一域名请求间隔 ≥3 秒，单域名 ≤50 次/小时
4. **明确标识**：User-Agent 使用 `GovProcurementBot/1.0 (WorkBuddy-CN)`
5. **缓存优先**：24 小时内不重复请求相同页面
6. **遇阻即停**：403/429/503 立即停止该域名采集

### 禁止行为（法律红线）

| 禁止行为 | 法律风险 | 本 Skill 的对应措施 |
|----------|----------|---------------------|
| 破解验证码 | 违反《网络安全法》第27条 | 遇验证码立即跳过，不尝试任何方式通过 |
| 绕过登录/付费墙 | 违反《计算机信息系统安全条例》 | 需登录/付费的页面一律跳过，标记为"不可用" |
| 使用代理池轮换 IP | 构成规避安全保护措施 | 单 IP + 频率限制，不轮换不伪装 |
| 伪造身份/指纹 | 构成身份欺诈 | 使用透明可识别的 User-Agent |
| 采集非公开信息 | 违反《个人信息保护法》 | 仅采集公开公告，不采集评委/专家等个人信息 |
| 转售原始数据 | 违反平台使用条款 | 数据仅用于用户自身分析，不二次分发 |

## 19. 围标串标检测增强

**输入**：项目信息 + 工商/司法/历史投标数据
**输出**：围标串标风险报告（风险评分 + 关联路径 + 判定依据 + 建议复核项）

**定位**：本模块是 v4.9 核心升级，将模块 5「采购合规审计辅助」的基础检测（等差/等比报价序列分析、关联企业碰撞、联系方式雷同）升级为**多跳图分析 + 异常模式挖掘 + 历史行为追踪**。从「有没有违规特征」升级为「为什么怀疑、依据是什么、如何复核」。

**工作流**：
```
1. 接收项目信息（招标编号/参与企业列表）

5. 输出可解释性风险报告（含人工复核建议项）
```

## 23. 意图路由器（全局架构）

**输入**：用户自然语言消息 / 语音转文本消息
**输出**：路由到对应模块的执行指令 + 消歧说明（如触发）

**定位**：本模块是 v5.0 新增的全局架构组件，**不属于19个功能模块之一**，而是横跨所有模块的「调度中心」。v5.2 新增语音输入指令解析能力，支持外勤场景口语化指令识别。

**工作流**：
```
1. 接收用户消息（文本 / 语音转文本）
2. 预处理：分词 → 去除停用词 → 提取核心意图
3. 口语化指令解析（v5.2 新增）：
   - 口语化表达识别（如"查一下本周苏州的医疗设备标"）
   - 填充词去除（如"帮我""看一下""那个"）
   - 区域/品类/时间实体提取
4. 三级匹配：
   - Level 1：核心词精确匹配（如"写标书"→模块16，置信度100%）
   - Level 2：同义词/模糊匹配（如"帮我写投标文件"→模块16，置信度85%）
   - Level 3：上下文感知匹配（结合对话历史消歧，置信度70%）
5. 如果置信度 <70% 或 Top2 置信度差 <15%：
   → 触发消歧询问（提供最多3个候选意图）
6. 路由到对应模块执行
```

**语音输入指令解析（v5.2 新增）**：

外勤场景下，用户可通过手机输入法语音转文本或手动输入口语化指令，路由器自动解析：

| 口语化指令 | 解析结果 | 路由模块 |
|-----------|---------|---------|
| "查一下本周苏州的医疗设备标" | 区域=苏州, 品类=医疗设备, 时间=本周 | 模块1 商机发现 |
| "把这个标加关注" | 操作=加关注, 对象=当前项目 | 模块21 盯标推送 |
| "看看XX公司有没有问题" | 操作=背调, 对象=XX公司 | 模块4 供应商背调 |
| "这个标能不能投" | 操作=投标分析, 对象=当前项目 | 模块2 投标决策 |
| "资质快到期了帮我看看" | 操作=资质预警 | 模块16.6 资质缺漏预警 |
| "我们上次投的怎么样" | 操作=复盘查询 | 模块21.1 投标复盘 |

**口语化解析规则**：
```
1. 填充词过滤：去除"帮我""看一下""那个""这个""啊""吧"等语气词
2. 区域实体：匹配省/市/区关键词（如"苏州""北京""朝阳区"）
3. 品类实体：匹配IT/医疗/工程/物业等品类关键词
4. 时间实体：匹配"本周""本月""最近""上半年"等时间词
5. 操作实体：匹配"查""找""分析""加""看"等操作动词
6. 无法解析时 → 引导用户补充关键信息（区域/品类/操作）
```

**三级匹配规则**：

| 级别 | 匹配方式 | 示例 | 置信度 |
|------|---------|------|--------|
| L1 精确 | 核心触发词完全匹配 | "写标书"、"查企业"、"围标检测" | 100% |
| L2 同义词 | 同义词表+模糊匹配 | "帮我写投标文件"、"查一下XX公司"、"围串标检查" | 70-95% |
| L3 上下文 | 对话历史+语义理解 | 上句"竞争对手分析"→本句"报价"指"竞对报价" | 60-80% |

**消歧策略**（多意图冲突时）：

| 冲突类型 | 示例输入 | 消歧方式 |
|---------|---------|---------|
| 多模块等置信度 | "分析一下"（模块2/17/18都可能） | 提供候选列表让用户选择 |
| 长句多任务 | "查XX公司+找北京IT项目" | 按优先级表拆分，先执行高优先级任务 |

| 模糊范围 | "最近有什么政策"（行业？地区？） | 使用用户默认配置（已配置）或全行业 |

**触发词精简重组**（v5.0 50+ → 三级结构）：

| 核心词（L1） | 同义词（L2） | 误触发防护（排除词） |
|-------------|-------------|-------------------|

**FAQ**：

> **Q：为什么有时要问我是哪个意图？是不是 Skill 出问题了？**
> A：不是。当你说的话有歧义（比如只说"分析一下"），Skill 会问你是想分析项目、分析企业还是分析报价。这是为了帮你做对事，不是出错。回答后路由器会记住偏好，后续同类输入直接路由。

> **Q：可以关闭意图路由器，直接用触发词吗？**
> 可以。发送"精确模式"后，只接受L1精确触发词，不再做消歧，执行速度更快。发送"智能模式"恢复三级匹配。

## 24. 数据飞轮引擎

**输入**：系统自动运行 + 用户配置（竞对关注清单、关注地区、关注品类）
**输出**：中标结果回流入库 + 价格指数报告 + 复盘链自动串联 + 竞对动态推送 + 爬虫自愈状态

**定位**：本模块是 v5.1 核心升级，将 skill 从「单次分析工具」升级为「越用越准的数据资产」。中标结果回流建立第一方数据底座；行业价格指数把分散中标数据汇聚为可比指标；复盘链自动串联让每次投标经验自动沉淀；竞对实时监控把静态画像升级为动态预警；爬虫失效自愈降低 31 省分网维护成本。五大升级形成数据飞轮——数据越多越准，越准越多数据。

**工作流**：
```
1. 定时采集（模块1）→ 抓取招标公告 + 中标公告
2. 中标公告 → 解析中标金额/中标人/评标明细（可得时）→ 双因子去重 → 入库星型模型
3. 星型模型 → 按行业×区域×季度聚合 → 行业价格指数（基准期=100）
4. 中标结果 → 比对知识库 → 如用户投过 → 自动提示复盘 → 确认后入知识库
5. 关注竞对清单 → 定时采集竞对公告/中标/变更 → 哈希变更检测 → 企微/钉钉推送
6. 爬虫双选择器 → 主备切换 → 双失效记录 → 降权重调度
```

### 24.3 行业价格指数

**计算公式**：
```
指数 = (当期均价 / 基期均价) × 100
基期 = 滚动最近4个季度
分位数输出：P25（低价位）/ P50（中位数）/ P75（高价位）
聚合维度：行业（品类编码）× 区域（省/市）× 季度
```

**输出**：

**双向使用**：

### 24.5 竞对实时监控

**配置**：发送"配置关注竞对" → 输入竞对名称清单 + 关注维度

### 24.6 爬虫失效自愈

**机制**：每个采集源配双套选择器（主+备），页面结构哈希监测失效自动切换

**自愈流程**：
```
采集源A → 主选择器采集 → 成功 → 继续
                    → 失败 → 切换备选择器 → 成功 → 记录主选择器待修
                                       → 失败 → 记录待修清单 + 降权重
                                               → 下次采集跳过该源
                                               → 每日重试待修清单
```

**调度权重计算**：
```
权重 = 成功率 × 0.8 + 响应速度因子 × 0.2
成功率 = 成功次数 / 总采集次数（滑动窗口：最近50次）
权重 < 0.3 → 暂停采集，进入待修清单
权重 0.3-0.6 → 降低采集频率（间隔 × 2）
权重 > 0.6 → 正常采集
```

**待修清单输出**：
```
⚠️ 爬虫自愈状态报告

总采集源：33（ccgp + 31省 + 公共资源平台）
正常：28 | 降权：3 | 待修：2

━━ 待修清单 ━━
| 采集源 | 故障类型 | 最后成功 | 自愈尝试 |
|--------|---------|---------|---------|
| 某省采购网 | 主备选择器均失效 | 2026-08-15 | 人工修复CSS路径 |
| 某市交易平台 | 页面结构改版 | 2026-08-18 | 等待备选适配 |
```

## 25. 标书协作引擎（全局架构）

**输入**：项目信息 + 团队成员清单 + 分工指令
**输出**：章节任务表 + 文件哈希锁表 + 合并审校报告 + 资质OCR离线填充

**定位**：本模块是 v5.2 新增的全局架构组件，解决多人协作编写标书时的「并发冲突、版本失控、一致性差」三大痛点。通过章节任务拆分实现责任到人，通过文件哈希锁防止并发覆盖，通过合并审校确保全文一致性，通过资质OCR离线化降低外勤场景依赖。

**工作流**：
```
1. 项目创建 → 自动拆解为标准章节任务表（章节/负责人/状态/截止）
2. 成员领取章节 → 哈希锁表锁定该章节（防并发覆盖）
3. 成员完成章节 → 释放锁 + 更新状态
4. 所有章节完成 → 触发合并审校（全文一致性检查）
5. 审校通过 → 输出最终标书
6. 资质文件 → PaddleOCR离线识别 → 证书版式库定位字段 → 自动填充
```

### 25.2 文件哈希锁表防并发覆盖

**锁表机制**：
```
1. 成员A编辑章节X → 获取锁（lock_acquire）
2. 成员B尝试编辑章节X → 返回"该章节已被A锁定，请等待或协调"
3. 成员A保存章节X → 计算SHA-256哈希 → 释放锁（lock_release）
4. 若成员A异常退出（超时30分钟）→ 自动释放锁（lock_timeout）
```

**锁表结构（gov_collab.db，运行时生成，存放于 `~/.workbuddy/output/`）**：
```sql
CREATE TABLE chapter_locks (
    id INTEGER PRIMARY KEY,
    project_id TEXT NOT NULL,
    chapter_name TEXT NOT NULL,
    member_name TEXT NOT NULL,
    lock_time TEXT NOT NULL,
    lock_status TEXT DEFAULT 'locked',
    file_hash TEXT,
    UNIQUE(project_id, chapter_name)
);

CREATE TABLE chapter_versions (
    id INTEGER PRIMARY KEY,
    project_id TEXT NOT NULL,
    chapter_name TEXT NOT NULL,
    version_num INTEGER NOT NULL,
    member_name TEXT NOT NULL,
    save_time TEXT NOT NULL,
    file_hash TEXT NOT NULL,
    change_summary TEXT
);
```

**防覆盖提示**：
```
⚠️ 章节锁定提示
章节「技术方案」已被 李四 锁定（锁定时间：14:30）
- 请等待李四完成编辑
- 如需紧急编辑，发送"强制解锁"（需项目负责人确认）
```

### 25.3 合并审校（全文一致性检查）

**触发条件**：所有章节状态为「已完成」或用户发送"合并审校"

```

   - 检查图表编号是否连续（如图1、图2、图4缺图3）

   - 提取全文专业术语（建立术语统一表）
   - 检查术语使用是否一致（如"甲方"vs"采购人"vs"采购单位"）

   - 页码/页眉页脚一致性
   - 表格/图表标题格式
   
4. 资质数据一致性
   - 资质名称在全文中是否统一
   - 有效期数据是否一致
   - 金额数据是否一致
```

## 边界与限制

**此 Skill 不处理**：
- ❌ 政府采购预算编制（预算编制是采购人职责，但可辅助测算）
- ❌ 项目验收评审（需线下专家参与，但可提供验收标准分析）
- ❌ 政府采购投诉处理流程（涉及行政程序，但可提供流程指引和材料模板）
- ❌ 供应商财务审计（需注册会计师执行）
- ❌ 非政府采购的商业招标（如企业采购、军队采购需其他模块）

**数据限制**：
- 仅基于公开信息分析，无法访问内部/涉密数据
- 历史中标数据随平台更新可能有延迟（一般 1-3 天）
- 中标概率评估基于统计模型，不保证结果
- Skill 仅提供分析建议，最终决策由用户自行承担

## 反模式（绝对不要这样做）

> 评测反馈："什么不该做写得很清楚，重要警告有特别标注。" ✅ 本节扩展更新，并新增决策导航。

### 底线三问

在执行业务指令前，需先如下自问：
1. **"这是不是违法的？"** → 如果是，**立即拒绝**
2. **"是不是帮用户做违法的事？"** → 如果是，**立即拒绝**
3. **"有没有合法的替代方案？"** → 如果有，**拒绝违法部分 + 提供替代方案**

> 示例：用户说"帮我围标" → 触发底线第1条，拒绝 → 提供合规替代（围标串标合规检测）

### 违规行为速查表

| 用户意图 | Skill 回应 | 替代方案 |
|----------|-----------|---------|
| "帮我围标" 或 "帮我串通投标" | ❌ **拒绝执行**。提示："围标串标是违法行为，依据《招标投标法》第 53 条，可处中标项目金额 5‰-10‰ 罚款。本 Skill 仅提供合规检测，不协助违法行为。" | 🔄 我可以帮你做**围标串标合规检测**，及时发现项目中的围标特征，保护你自己不被牵连 |

| "帮我查评委名单" | ❌ **拒绝执行**。评审专家信息在评标前属于保密信息。 | 🔄 我可以帮你分析**评分方法是否合理**，提出质疑建议 |
