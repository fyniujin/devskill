# 国内可用搜索引擎指南

本文档说明 strict 模式下各引擎的国内可用性、隐私保护级别和自动降级策略。

## 引擎对比

| 引擎 | 国家 | 国内速度 | 隐私保护 | 数据收集 | 追踪 | strict 默认 | 备注 |
|------|------|---------|---------|---------|------|-----------|------|
| **SearXNG（本地）** | 本机 | ⭐⭐⭐⭐⭐ 极快 | 极高 | ❌ 无 | ❌ 无 | ✅ 最优先 | query 不出本机，最佳隐私 |
| **Yandex** | 俄罗斯 | ⭐⭐⭐⭐ 快 | 中等 | 部分 | 少量 | ✅ | 俄文界面可用，中文搜索能力较好 |
| **Startpage** | 荷兰 | ⭐⭐⭐ 中等 | 高 | ❌ 无 | ❌ 无 | ✅ | Google 代理，结果质量高 |
| **Qwant** | 法国 | ⭐⭐⭐ 中等 | 高 | ❌ 无 | ❌ 无 | ✅ | 欧洲隐私法保护 |
| **Brave** | 美国 | ⭐⭐ 较慢 | 高 | ❌ 无 | ❌ 无 | ✅ | 独立搜索引擎，不依赖 Google |
| **DuckDuckGo** | 美国 | ⭐ 不稳定 | 极高 | ❌ 无 | ❌ 无 | ⚠️ 最后 | 国内连接不稳定，仅作兜底 |

## 自动降级策略

```
strict 模式搜索流程：
┌──────────────────────────────────────────────────────┐
│              SearXNG（本地，最优先）                    │
│              query 不出本机，极速响应                   │
└────────────────────┬─────────────────────────────────┘
                     │ (不可用时)
                     ▼
┌──────────────────────────────────────────────────────┐
│              Yandex + Startpage + Qwant + Brave      │
│              并发请求，SimHash 去重                    │
└────────────────────┬─────────────────────────────────┘
                     │ (全部失败时)
                     ▼
┌──────────────────────────────────────────────────────┐
│              DuckDuckGo（不稳定时使用）                 │
└────────────────────┬─────────────────────────────────┘
                     │ (仍失败时)
                     ▼
┌──────────────────────────────────────────────────────┐
│          默认：停止搜索并提示，不泄露查询词             │
│          显式加 --allow-fallback 才降级到 bing/baidu   │
└──────────────────────────────────────────────────────┘
```

### 为什么默认不降级

strict 模式的用户预期是「宁可没有结果，也不把查询词发给隐私保护不足的引擎」。
静默降级到百度/必应会让用户在毫不知情的情况下失去隐私保护，属于违背预期的危险默认值。
因此 V1.2 起改为默认拒绝，需通过 `--allow-fallback` 或配置项 `privacy.strict.allow_fallback` 显式授权。

同理，strict 模式下即使用 `--engines baidu` 显式指定，也会被拒绝并提示改用 normal 模式。

## 推荐使用方式

### 最佳隐私（推荐）
```bash
python scripts/search.py "关键词" --privacy strict --engines searxng,yandex,startpage
```
- query 完全在本地
- Yandex + Startpage 作为离线后备

### 最佳速度
```bash
python scripts/search.py "关键词" --engines baidu,bing
```
- 国内引擎最快
- normal 模式下的推荐选择

### 平衡模式
```bash
python scripts/search.py "关键词" --privacy strict --engines yandex,searxng
```
- 速度隐私均衡
- Yandex 国内速度快 + SearXNG 极致隐私

## 常见问题：特定引擎故障

### Yandex 故障
- 可能原因：反爬升级、IP 限制
- 解决：等待自动降级到 Startpage/Qwant

### 全部 strict 引擎失败
- 可能原因：网络受限、DNS 污染
- 解决：
  ```bash
  1. 检查网络：ping yandex.com
  2. 配置代理（config.yaml 中 search.proxy）
  3. 降级使用 normal 模式
  ```

### DDG 在国内不可用
- 常见现象，自动使用其他隐私引擎替代
- 配置 `privacy.strict.proxy` 后可恢复

### 判断是引擎坏了还是关键词没匹配

```bash
python scripts/search.py --selftest
```

输出会区分「正常」「确认无结果」「被拦截」「选择器失效」四种状态。
显示「选择器失效」说明该引擎改版了，需更新插件版本；「被拦截」则是触发风控，降低频率后重试。

## 限制与规避

| 问题 | 影响 | 规避方式 |
|------|------|---------|
| 搜索引擎改版 | HTML 解析失败 | 多套备选选择器自动尝试，仍失败则等待版本更新 |
| 触发风控 | 返回验证码页 | 降低 `daily_request_limit`，增大请求间隔 |
| CDN 劫持 | 结果被篡改 | 全程 HTTPS + 多引擎交叉验证 |
| DNS 污染 | 域名解析到错误 IP | 配置 `privacy.strict.proxy` |
| IP 过滤 | 特定 IP 被封锁 | 配置代理，或改用本地 SearXNG |
| 跳转链接 | 国内引擎返回中转地址 | 排序时自动识别并降权 |
